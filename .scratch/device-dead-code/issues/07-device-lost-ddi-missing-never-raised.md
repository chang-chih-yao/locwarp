## 為什麼

`DeviceLostError` 有一個原因 `REASON_DDI_MISSING`，後端和前端都為它準備了提示文字。但沒有任何地方用這個原因丟出 `DeviceLostError`，所以使用者永遠看不到這段提示。讀 code 的人卻會以為，LocWarp 偵測得到 DDI 被卸載。

提示的內容也有問題：它叫人「重新插拔 USB 或重新啟動裝置」。可是 personalized DDI 通常重新開機就會卸載，照做反而更糟。05 號票的實機查證清單就是用重開機來卸載 DDI，這點還沒在實機上確認。

下面的行號都是 `eebf97e` 時的位置，開票時逐一對過。動手前以內容為準，先用 grep 再對一次。

## 現況

- 定義在 `backend/services/location_service.py`：
  - `:43` 是 `REASON_DDI_MISSING = "ddi_missing"`。
  - `:36` 類別 docstring 列了它：「Personalized DDI is no longer mounted」。
  - `:47-49` 建構子的 `reason` 預設是 `"unknown"`。
- 提示文字有兩處：
  - 後端 `backend/api/location.py:111-113`（`_DEVICE_LOST_REASON_MESSAGES`），只有中文：「Developer Disk Image 未掛載,請重新插拔 USB 或重新啟動裝置」。
  - 前端 `frontend/src/services/api.ts:46-49` 的 `device_lost_ddi_missing`，中英文都有。前端用 `code` 加 `reason` 組出 key 來查（`:96-101`）。
- 實際丟出 `DeviceLostError` 的地方，只用了三種原因：
  - `backend/core/device_manager.py:794` 是 `USB_GONE`，`:813` 是 `TUNNEL_DEAD`，`:831` 是 `LOCKDOWN_DEAD`。
  - `backend/services/location_service.py:150`、`:156`、`:187`、`:290` 都是 `LOCKDOWN_DEAD`。
- `git grep -n -e DDI_MISSING -e ddi_missing -- ':!.scratch'` 只有上面四處：`location_service.py:36`、`:43`，`api/location.py:111`，`api.ts:46`。`tests/` 沒有用到。
- 歷史：`git log -S REASON_DDI_MISSING` 和 `git log -S ddi_missing` 都只找到 `d976d67`（v0.2.120），就是加入它的 commit。從那時起就沒有地方丟過。
- 05 號票搜的是「未偵測到 DDI」和「No DDI detected」。這段寫的是「未掛載」，所以 05 號票開票時沒搜到。

## 可能的做法

- A. 拿掉：`REASON_DDI_MISSING`、docstring 那行，和後端、前端的兩段提示一起拿掉。
- B. 留著這個原因，只改提示文字，不叫人重開機。但它還是不會被丟出來，等於留著一段沒用到的程式。
- C. 接上：在偵測到 DDI 被卸載的地方丟它。這是新功能，要先知道怎麼偵測，跟 05 號票的實機查證有關。
