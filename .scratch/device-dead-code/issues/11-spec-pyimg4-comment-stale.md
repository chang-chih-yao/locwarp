## 為什麼

`backend/locwarp-backend.spec` 有一段註解，解釋為什麼打包時要另外帶上 pyimg4 的 metadata。它說少了 metadata 會讓 DDI 沒預先掛好的 iOS 17+ 手機出現 `No such service: com.apple.instruments.dtservicehub`。

這個因果是 v0.2.54 寫的，那時 LocWarp 會自動掛載 personalized DDI。v0.2.58 起 LocWarp 不再掛載，只檢查。現在 DDI 沒預先掛好的手機，不管有沒有 metadata，DVT 都打不開。讀這段的人會以為帶上 metadata 就能避免這個錯誤。

打包的設定本身（`collect_all`、`copy_metadata`）沒有問題，這張只談註解。

下面的行號都是 `9753c48` 時的位置，開票時逐一對過。動手前以內容為準，先用 grep 再對一次。

## 現況

註解全文（`backend/locwarp-backend.spec:27-36`）：

```python
# pyimg4 is an indirect dep of mobile_image_mounter's Personalized DDI path.
# pymobiledevice3 calls importlib.metadata.distribution('pyimg4') at import
# time. collect_all('pymobiledevice3') pulls pyimg4's .py files in as
# transitive imports, but NOT its .dist-info metadata directory, so the
# metadata lookup raises PackageNotFoundError and the whole
# mobile_image_mounter import fails. That cascades into "No such service:
# com.apple.instruments.dtservicehub" on iOS 17+ devices whose DDI was never
# pre-mounted by another tool. copy_metadata pulls the dist-info dir into
# the bundle so importlib.metadata finds it. Also collect_all for the
# python files and any companion binaries.
```

逐句對過：

- 「少了 metadata，`mobile_image_mounter` 整個 import 失敗」：**還成立**，但細節變了。
  - 在 pymobiledevice3 11.49.5，查 metadata 的是 pyimg4 自己：`pyimg4/__init__.py:7` 的 `__version__ = version(__package__)`。註解寫的是 pymobiledevice3 呼叫 `importlib.metadata.distribution('pyimg4')`。
  - import 的路徑是 `mobile_image_mounter` → `restore/tss.py:13` → `restore/img4.py:5` → `pyimg4`。
  - 在 `.venv` 試過：`import pymobiledevice3.services.mobile_image_mounter` 之後，`pyimg4` 和 `pymobiledevice3.restore.img4` 都在 `sys.modules` 裡。
  - 沒有實際拿掉 metadata 打包來試。
- 「That cascades into "No such service: com.apple.instruments.dtservicehub" on iOS 17+ devices whose DDI was never pre-mounted」：**已經不是這個因果**。
  - `a22fe11`（v0.2.54）寫這段時，import 失敗代表 LocWarp 沒辦法幫手機掛 DDI，所以 DVT 打不開。
  - `051de0e`（v0.2.58）拿掉自動掛載。現在 import 失敗只會讓 `_check_personalized_ddi_mounted` 記一行 warning、跳過查詢（`backend/core/device_manager.py:448-455`）。
  - `b847d3d`（v0.2.206）之後，RSD 有廣播 DVT 的服務時，根本不會去 import `mobile_image_mounter`（`device_manager.py:434-446`）。
  - DDI 沒預先掛好的手機，不管 import 成不成功，DVT 都打不開，接著退回 `LegacyLocationService`。
- 同一個檔案上面那段 `developer_disk_image` 的註解（`:19-24`），`c20a1b6` 已經改寫成現況：import 失敗時，iOS 17+ 的 DDI 檢查會跳過查詢。這段沒有跟著改。
- 上游 `upstream/main` 的這段註解一字不差。這裡改了，之後合併上游碰到這幾行會衝突。

`a22fe11` 的 commit 訊息另外記了一件事，跟 05 號票有關：

- 那次的使用者回報是兩台 iPhone，其中一台每次瞬移都丟 `InvalidServiceError`。commit 訊息寫的原因是那台的 DDI 從來沒掛過，DVT 的服務不在，退回的 legacy 服務就丟 `InvalidService`。
- 05 號票「沒追的」第一項，就是 DDI 沒掛、退回 Legacy 後瞬移失敗時，手機回哪個錯誤碼。這是 v0.2.52 時的回報，可以當線索，不能代替 05 號票的實機查證。

  - 現在的後果是 iOS 17+ 的 DDI 檢查會跳過查詢，跟上面 `:19-24` 那段的寫法一致。
