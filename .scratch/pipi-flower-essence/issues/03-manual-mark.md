# 03 在花的 popup 手動標記拿過精華、也能取消

Status: ready-for-agent
Blocked by: 02
Spec: `.scratch/pipi-flower-essence/spec.md`

## 做什麼

已盛開、還沒枯萎的花，popup 裡會出現「我拿過精華了」按鈕，放在「瞬移+撈水果」右邊，兩顆一樣寬。

- **按下之後**：等原站確認成功。沒勾「顯示拿過精華的花」時，popup 關掉、花消失；有勾時，popup 留著，按鈕變成「已拿過精華（取消）」，花加上 ✓。
- **取消**：再按一次就取消標記。
- **跟原站同步**：標記寫進原站帳號，手機上的原站也看得到。

## 驗收條件

- [ ] 後端可以設定標記：client 新增設定標記的方法，加上 `PUT /api/pipi/essence`。
  - body 和回覆的形狀照 spec「後端」。id 原樣轉給原站，保留數字或字串的型別。
  - body 用 pydantic 嚴格驗證：字串或整數的 id 有長度上限，盛開時間是正整數，`collected` 是布林值。
  - 不快取，跟 items 走同一條排隊和間隔路徑。
  - 切面 A 的「設定」「不快取」「API body 驗證」測試要有，「錯誤」也要測設定這個方法：`PipiError` 照原樣往外拋。API 測試用暫時的 `SETTINGS_FILE`。
- [ ] 拿過精華模組能用設定回覆更新標記狀態：
  - 標記時用回覆的失效時間；回覆是 0 時，改用那朵花的 `wiltingMs`。
  - 取消時刪掉這個識別。
  - 不改動舊的狀態物件。
  - 套在「還沒讀到」的狀態上，結果仍然是還沒讀到。
  - 切面 B 的「設定回覆」測試要有。
- [ ] 花的規則模組新增「能不能標記拿過精華」（Q4），切面 C 的「能不能標記」測試全部要有。其中要有測試鎖住：
  - 跟撈水果的差別：沒有枯萎時間就不能標記。
  - 盛開時間有小數就不能標記，跟 `PUT` 只收正整數一致。01 號票實測發現盛開時間有小數時，照 spec 兩邊一起放寬。
- [ ] popup 的動作照 spec「圖層 → popup 的按鈕列」改：
  - 每個動作都改成收到整筆點位，不再只收座標；瞬移、導航、撈水果從裡面取座標，行為不變。04 號票的撈水果直接沿用這一點。
  - 共用的點擊處理不再先關 popup，改由各個動作決定：瞬移、導航、撈水果照舊先關；標記不關。
  - 標記按鈕要有自己的動作對應。
- [ ] popup 的按鈕列：
  - 兩顆按鈕在同一列、等寬，撈水果在左；只出現一顆時佔滿整列；兩顆都沒有時，整列不出現。
  - 按鈕文字在打開 popup 時，依當下是不是拿過精華來決定；還不知道時用「我拿過精華了」。
  - 在中文、英文介面下實際看過。會換行時，只把同時出現兩顆按鈕的 popup 加寬，其他 popup 寬度不變，按鈕文字也不改。
  - 加寬的做法照 spec：Leaflet 的 `minWidth`、`maxWidth` 在建立 marker 時就固定，現在的 `maxWidth` 280 會把內容夾住。同時有兩顆按鈕時，popup 內容加 class 撐開最小寬度，花的 marker 的 `maxWidth` 放寬到容納得下。
- [ ] 圖層提供一個標記動作，手動按鈕和 04 號票的自動標記共用它，行為照 spec「標記動作」：
  - **防重複送出**：標記動作自己記一份「存檔中」的識別清單，放在 ref、不放進 React state。同一朵花還在存檔中就直接忽略，不送第二次。
  - **存檔期間按鈕停用**：點下時直接把按鈕設成停用；popup 每次打開，包括整層重建後重開，都讀「存檔中」清單，把存檔中的花的按鈕畫成停用。
  - **接受 popup 關掉再重開**：標記成功會整層重建，有勾「顯示拿過精華的花」時 popup 靠既有的機制重開，內容照新的標記狀態重畫。不另外做就地更新。
  - **成功後**：沒勾時先關 popup 再更新標記狀態；有勾時 popup 留著。提示「已標記為拿過精華」或「已取消拿過精華標記」。
  - **失敗時**：跳錯誤提示，從「存檔中」清單拿掉；popup 還開著的話按鈕恢復可按。popup 不關，標記狀態不變；不自動重試，也不停掉抓取迴圈。
  - 圖層關著時也能用，04 號票需要這一點。
  - **提示的接線**：顯示 toast 的函式由 App 經 MapView 傳進圖層。
  - 中英文字串照 spec 的介面文字表。
- [ ] 實測原站，使用者已經同意（Q12）：
  - 動手前先告訴使用者要標哪一朵花。
  - 在 LocWarp 標記一次，到原站或手機上確認出現了；再取消，確認消失了。
  - 把設定回覆的實際格式寫進本票的 Comments。跟 spec 不一樣時，先改 spec 再繼續。
- [ ] 人工驗證，逐項回報：
  - spec「人工驗證」裡 popup、標記與取消的各項，包括「存檔中」：用 fetch 攔截延遲設定請求，連點只送出一次；延遲期間按「重新整理」讓整層重建，popup 重開時按鈕還是停用。
  - 用 fetch 攔截讓標記請求失敗：出現錯誤提示、按鈕恢復、花沒有被藏。
  - 自己按標記之後，沒有新的標記清單請求。
  - 瞬移、導航、撈水果三顆按鈕照舊會關掉 popup，而且走到的座標沒變。
- [ ] 文件：
  - 蘑菇地圖設計文件：Site protocol 補上設定標記和實測格式；新增一節「拿過精華」，寫按鈕條件、標記動作（含存檔中清單、接受 popup 關掉再重開）、跟原站刻意不同的地方；Throttling 補上設定請求。
  - rules 檔：Tests 那一行有新測試的話，補上去。
- [ ] 回歸：`tests/frontend/*.ts`、`tests/pipi/` 全部照跑，`npm run build` 要通過。逐條回報 mutation check 的結果，有任何 skipped 都要說明。
