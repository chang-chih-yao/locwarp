# 03 在花的 popup 手動標記拿過精華、也能取消

Status: resolved
Blocked by: 02
Spec: `.scratch/pipi-flower-essence/spec.md`

## 做什麼

已盛開、還沒枯萎的花，popup 裡會出現「我拿過精華了」按鈕，放在「瞬移+撈水果」右邊，兩顆一樣寬。

- **按下之後**：等原站確認成功。沒勾「顯示拿過精華的花」時，popup 關掉、花消失；有勾時，popup 留著，按鈕變成「已拿過精華（取消）」，花加上 ✓。
- **取消**：再按一次就取消標記。
- **跟原站同步**：標記寫進原站帳號，手機上的原站也看得到。

## 驗收條件

- [x] 後端可以設定標記：client 新增設定標記的方法，加上 `PUT /api/pipi/essence`。

  - body 用 pydantic 嚴格驗證：字串或整數的 id 有長度上限，盛開時間是正整數，`collected` 是布林值。

- [x] 圖層提供一個標記動作，手動按鈕和 04 號票的自動標記共用它，行為照 spec「標記動作」：
  - **只做四件事**：送出請求、管「存檔中」清單、用回覆更新標記狀態、回傳結果。結果分成三種：成功、失敗（帶原因）、存檔中所以忽略。
  - **不關 popup、不跳提示**：這兩件交給呼叫端。共用動作如果關 popup，自動標記成功時會把使用者當下開著的別朵花或書籤的 popup 關掉，圖層關著時也一樣；兩邊都跳提示的話，後一個會蓋掉前一個。
  - **防重複送出**：標記動作自己記一份「存檔中」的識別清單，放在 ref、不放進 React state。同一朵花還在存檔中就直接忽略，不送第二次，回傳「存檔中所以忽略」。失敗時從清單拿掉也是它的事。
  - 圖層關著時也能用，04 號票需要這一點。
- [x] 手動按鈕是標記動作的呼叫端，自己負責 popup 和提示：
  - **存檔期間按鈕停用**：點下時直接把按鈕設成停用；popup 每次打開，包括整層重建後重開，都讀「存檔中」清單，把存檔中的花的按鈕畫成停用。
  - **接受 popup 關掉再重開**：標記成功會整層重建，有勾「顯示拿過精華的花」時 popup 靠既有的機制重開，內容照新的標記狀態重畫。不另外做就地更新。
  - **成功後**：
    - 沒勾時，開著的 popup 正是這朵花才關掉。存檔期間使用者可能已經改開別朵花或書籤的 popup，那個不關。
    - 有勾時 popup 留著。
    - 提示「已標記為拿過精華」或「已取消拿過精華標記」。
  - **失敗時**：提示「標記拿過精華失敗：{error}」或「取消拿過精華標記失敗：{error}」；popup 還開著的話按鈕恢復可按。popup 不關，標記狀態不變；不自動重試，也不停掉抓取迴圈。
  - **存檔中所以忽略**：存檔期間按鈕是停用的，正常收不到；收到時不跳提示。
  - **接受的邊界**（2026-11-09 使用者確認）：勾著「顯示拿過精華的花」、標記狀態還沒讀到時標記成功，狀態仍然是還沒讀到，不會整層重建。開著的 popup 按鈕會一直停用，等清單回來、整層重建才恢復。只會發生在打開圖層後、清單回來前那 1～2 秒，不另外處理。
  - **提示的接線**：顯示 toast 的函式由 App 經 MapView 傳進圖層。
  - 中英文字串照 spec 的介面文字表，包括最後補的標記失敗、取消失敗兩行。
- [x] 實測原站，使用者已經同意（Q12）：
  - 動手前先告訴使用者要標哪一朵花。
  - 在 LocWarp 標記一次，到原站或手機上確認出現了；再取消，確認消失了。
  - 取消之後讀一次清單，看那一筆是被拿掉，還是留著並帶 `collected: false`（01 號票實測時每一筆都帶 `collected: true`，原站和 LocWarp 讀清單時都不看這個欄位）。

  - 量一筆標記都沒有時清單的格式：原站回 `items: []`，還是沒有 `items` 或是 null。後端只把 `items: []` 當成一筆都沒有，其他都報 `pipi_unavailable`，面板會一直顯示「精華標記讀取失敗」。

      - 原站會清掉失效的標記的話，清單就自然變空，這樣就量到了。
      - 清單回 `pipi_unavailable`（面板顯示「精華標記讀取失敗」）的話，就是格式不是 `items: []`，照下面最後一項處理。先確認不是網路或登入的錯誤。
      - 清單裡還留著那筆失效的標記，就是原站連失效的標記也留著，改用下面的量法。
    - 標記之前先讀一次清單。如果已經是空的，這一次就量到了，取消之後再讀一次確認。
    - 清單裡還有別的標記時（原站可能連失效的標記也留著），先回報使用者，由使用者決定要不要先在原站取消那些標記；取消之後，再取消本次的標記並讀一次清單。
    - 量不到的話，在本票的 Comments 記下「空清單格式沒量到」和原因，spec「還沒驗證」那一項留著。
    - 量到的不是 `items: []` 時，回報使用者，先改 spec 再改後端。
  - 把設定回覆的實際格式寫進本票的 Comments。跟 spec 不一樣時，先改 spec 再繼續。
