# 蘑菇地圖：花的「只顯示彩帶」與「顯示普花」篩選

Status: resolved

## Problem Statement

蘑菇地圖圖層打開「花」之後，地圖上的花非常多：2026-11-05 在台北市區 zoom 15 抽樣，一個畫面就有 600 朵花，其中 267 朵是普花（白色花朵、紅色花朵、黃色花朵、藍色花朵）。使用者真正想找的通常是兩類：

- 普花以外的花種。
- 彩帶花，也就是剛盛開、還在第一個小時內的花。

但它們被大量普花淹沒了。目前點位種類只能整個開或整個關「花」，沒辦法再往下篩。

原站 pipimushroom.com 有每個花種的勾選，還有一個「是否強制顯示彩帶花」。LocWarp 沒有這些，而且使用者不想照搬原站的「強制顯示」語意。

## Solution

在蘑菇地圖面板的「花」底下加兩個子選項：

- **只顯示彩帶**：初始值不勾。勾起來後只留下彩帶花。
- **顯示普花**：初始值勾。取消後拿掉普花，包含普花的花苞。

一朵花要同時通過這兩個條件才會顯示，「花」仍然是總開關：

| 只顯示彩帶 | 顯示普花 | 顯示哪些花 |
|---|---|---|
| ☐ | ☑ | 全部的花（包含彩帶花與花苞） |
| ☑ | ☑ | 全部彩帶花 |
| ☑ | ☐ | 普花以外的彩帶花 |
| ☐ | ☐ | 普花以外的所有花（包含花苞；普花的彩帶花也不顯示） |

此外，所有彩帶花的 marker 外框改成彩虹色。打開 popup 時，如果還在彩帶期內，會多一行「彩帶花 · 5:03 後結束」。

## User Stories

1. 身為玩家，我想取消「顯示普花」，讓地圖只剩普花以外的花種，這樣不用在幾百朵普花裡找。
2. 身為玩家，我想勾「只顯示彩帶」，讓地圖只剩彩帶花，這樣能直接去拿剛盛開的花。
3. 身為玩家，我想同時勾「只顯示彩帶」、取消「顯示普花」，只看普花以外的彩帶花，因為那是最稀有的組合。
4. 身為玩家，我想同時勾「只顯示彩帶」和「顯示普花」，看到所有彩帶花，不管花種。
5. 身為玩家，我希望兩個都不動（初始值）時看到全部的花，跟加這個功能之前一樣。
6. 身為玩家，我希望普花是依花種認定（白色花朵、紅色花朵、黃色花朵、藍色花朵），這樣白色天竺葵、白色櫻花這類同色的其他花種不會被一起藏掉。
7. 身為玩家，我希望取消「顯示普花」時，這四個花種的花苞也一起藏掉，因為花苞長大後一樣是普花。
8. 身為玩家，我希望「花」關掉時，不論兩個子選項怎麼勾，地圖上都不出現任何花，這樣「花」仍然是總開關。
9. 身為新使用者，我希望第一次打開蘑菇地圖時仍然只看到蘑菇，維持既有的初始值。
10. 身為玩家，我希望「花」關掉時兩個子選項變灰、不能按，這樣我知道它們現在沒有作用。
11. 身為玩家，我希望兩個子選項變灰時保留原本的勾選，重新打開「花」就恢復。
12. 身為玩家，我希望兩個子選項縮排放在點位種類那一列下方，一看就知道它們屬於「花」。
13. 身為玩家，我希望重開 LocWarp 後，兩個子選項維持我上次的選擇。
14. 身為玩家，我希望存下來的設定壞掉或缺項時，LocWarp 退回初始值，而不是整個圖層出錯。
15. 身為玩家，我想一眼從 marker 的彩虹外框認出哪些是彩帶花，即使沒有勾「只顯示彩帶」也一樣。
16. 身為玩家，我想在彩帶花的 popup 看到彩帶期還剩多久，好判斷趕不趕得到。
17. 身為玩家，如果 popup 打開時彩帶期已經過了，我不希望看到負的倒數或過期的彩帶資訊。
18. 身為玩家，我能接受彩帶期剛結束的花，在下次重新抓資料或切換篩選前還留在地圖上。視窗在前景、抓資料順利時，最多約 60 秒；遇到原站限流或抓取失敗，舊資料會留到下次抓成功，期間彩帶狀態也不會更新。
19. 身為英文介面使用者，我想看到「Ribbon flowers only」和「Show common flowers」兩個標籤。
20. 身為玩家，我希望狀態列顯示的筆數是篩選後實際畫出來的數量。
21. 身為玩家，我希望被篩掉的花不佔用 LocWarp 自己的 marker 上限。原站回傳資料時就已經截掉的花，篩選救不回來；這種情況狀態列照舊顯示資料被截斷。
22. 身為玩家，我希望蘑菇和煙霧完全不受這兩個花的子選項影響。
23. 身為原站的使用者，我不希望 LocWarp 因為多了篩選，就對 pipimushroom.com 發出更多或不同的請求。切換子選項只重畫 marker，不重新抓資料。
24. 身為維護者，我希望普花和彩帶花的認定集中在一個能單獨測試的地方，原站資料格式改了的時候只要改一處。

## Implementation Decisions

**篩選狀態**

- 新增「花的子篩選」設定，內容是兩個布林值：只顯示彩帶（初始值 false）、顯示普花（初始值 true）。
- 型別、初始值、resolver 都放在集中存放初始值的模組，與點位種類並列。這是唯一的定義處，其他地方都引用它，不另外宣告。存檔的 JSON 形狀：

  ```ts
  { ribbonOnly: boolean; showCommon: boolean }
  ```

- resolver 把 localStorage 存的 JSON 還原成完整設定，行為比照點位種類的 resolver：
  - 每個欄位保留存過的布林值。
  - 缺少或不是布林值的欄位用初始值。
  - 整份不是 JSON 物件時全部用初始值。
- 存在新的 localStorage key `locwarp.pipi_flower_filter`，不併進既有的點位種類 key，避免改動既有的點位種類形狀和它的測試。

**新的純函式模組：判斷花**

- 這個模組在執行期不 import 任何東西，只用 TypeScript 可被直接抹除的語法，讓 `node --test` 可以直接載入。
  - 子篩選型別和點位資料型別用 type-only import 取自既有定義。Node 會把整行 type-only import 抹掉，不會去解析路徑。這點已在 Node v24.20 驗證過，所以不違反上面的限制。
- 對外提供三個判斷：
  - 一筆點位是不是普花。
  - 一筆點位是不是彩帶花，給定伺服器時間（毫秒）。是的話一併給出彩帶期結束時間，不是就沒有值。這個判斷不需要子篩選，popup 也用它。
  - 給定點位、子篩選、伺服器時間，這筆點位要不要顯示。
- 普花的認定：`key` **完全等於**下面四個之一。不用「品種是 Common」這種規則推斷，也不用中文名稱比對。

  | key | 花種 |
  |---|---|
  | `f:White:Common` | 白色花朵 |
  | `f:Red:Common` | 紅色花朵 |
  | `f:Yellow:Common` | 黃色花朵 |
  | `f:Blue:Common` | 藍色花朵 |

  花苞也帶相同的 key，所以會一起被認定成普花。假如將來出現 `f:Purple:Common`（紫色花朵），它**不是**普花。
- 花苞的認定：把 `state` 去頭尾空白、拿掉空白／底線／連字號、轉小寫後，等於 `leaf`、`bud`、`preflower` 其中之一。這跟原站的正規化方式相同，原站也把這三種都標成「花苞」。
- 彩帶花的認定，以下全部成立：
  - `itemKind` 是 flower，而且不是花苞。
  - `bloomedMs`、`wiltingMs` 都是有限的數字，而且大於 0。後端把原站的值原樣轉過來，沒有檢查型別；字串之類的值一律視為沒有值，不算彩帶花。
  - `bloomedMs ≤ now < wiltingMs`。
  - `now < bloomedMs + 60 分鐘`。

  彩帶期結束時間取 `bloomedMs + 60 分鐘` 和 `wiltingMs` 中較早的那個。
- 顯示規則：
  - 不是花的點位（蘑菇、煙霧）一律顯示，也一律不是彩帶花。
  - 花的話：勾了只顯示彩帶，就必須是彩帶花；沒勾顯示普花，就不能是普花。兩條都要成立。
- 「花」總開關、點位種類的開關，仍由既有的點位種類篩選處理，新模組不碰。
- `now` 一律用伺服器時間（本機時間加上偏移量），與既有的到期判斷一致。

**圖層**

- 建立 marker 時的順序：
  1. 先套既有的點位種類篩選和到期判斷。
  2. 通過的**每一筆**點位（不只花）都交給新模組判斷要不要顯示。這樣「蘑菇、煙霧不受影響」由模組負責，模組的測試才守得住。
  3. 最後才計入 marker 上限。被篩掉的花不佔上限。
- 子篩選只加進「建立 marker」那個 effect 的相依項，**不能**加進抓資料那個 effect。抓資料的 effect 重跑時會清掉上次抓取的範圍紀錄，然後立刻真的打一次 items API。點位種類現在就是這樣做的，照著做。
- 是不是彩帶花，只在圖層重建時重新判斷。會重建的時機有：抓到新資料、切換點位種類或花的子篩選、開關圖層。
- 每 30 秒的 prune 維持現狀，只依枯萎或結束時間拿掉 marker，**不**因為彩帶期結束而拿掉。
- marker icon 的快取鍵要包含「是否為彩帶花」，彩帶花才會拿到不同外框的 icon。
- 彩帶花的外框：
  - 把花原本 2px 的粉紅外框換成彩虹漸層的圓環。marker 尺寸和錨點不變，仍是 30px。
  - 所有彩帶花都這樣顯示，跟子篩選怎麼勾無關。不照抄原站的彩帶圖。
  - 現有內層元素有 `overflow: hidden`，在它裡面用偽元素畫圓環會被裁掉。漸層圓環要畫在不會被裁的地方，例如讓圓環本身當外層、用漸層背景加內距露出邊。
- popup 的彩帶行：
  - 內容在打開當下產生，不每秒更新，與既有的剩餘時間行一致。想看最新數字就重開 popup。
  - 打開時用當下的伺服器時間再呼叫一次模組的彩帶判斷，不沿用圖層重建時的結果。是彩帶花才加這一行，否則不加。這樣「不顯示過期或負的倒數」由模組的邊界測試守住。
  - 文字：中文「彩帶花 · {time} 後結束」，英文「Ribbon · ends in {time}」。故意不用「剩」，避免跟下一行既有的「剩 22:41:00 · 15:30 凋謝」混淆。
  - `{time}` 沿用既有的剩餘時間格式：分不補零、秒補零，例如 `5:03`、`59:59`。彩帶期不到一小時，所以不會出現小時。

**面板**

- 在點位種類 chip 那一列下方，縮排放兩個勾選框，順序是「只顯示彩帶」、「顯示普花」。
- 「花」關掉時兩個都 disabled，但保留原本的勾選值。兩者之間互不影響，不會因為其中一個而讓另一個變灰。
- 標籤文字：中文「只顯示彩帶」、「顯示普花」；英文「Ribbon flowers only」、「Show common flowers」。
- 狀態由地圖元件持有，並寫回 localStorage，做法比照點位種類：
  - 面板拿到值和變更 callback。
  - 圖層 hook 只拿到值，跟現有的點位種類一樣。

**後端與上游**

- 不改後端。後端已經把 `key`、`state`、`bloomedMs`、`wiltingMs` 轉給前端。
- 不改送往 pipimushroom.com 的請求。原站本身也是在瀏覽器端篩選，抓資料時不帶任何篩選條件，所以這個功能不會增加原站的負擔，也不會改變資料被截斷的行為。

## Testing Decisions

**怎樣算好的測試**

- 只透過模組對外的判斷函式測試，驗證「哪些點位會顯示、哪些是彩帶花、彩帶期何時結束」。不測內部的中間值。
- 以 2026-11-05 抽樣看到的真實格式為主，也就是真實的 key、state 和時間欄位。
- 有些規則用真實資料測不出來。例如真實花苞的時間欄位都是 0，光靠「時間要大於 0」就判不成彩帶花，拿掉「不是花苞」那條規則測試照樣全綠。
  - 這種規則允許用合成資料，例如帶著盛開時間的花苞、`wiltingMs` 早於盛開後 60 分鐘的花、字串型別的時間欄位。
  - 合成資料的測試名稱要寫明它在防哪種原站格式變化。
- 測試名稱用繁體中文寫出要守住的意圖，比照 `tests/frontend/test_defaults.ts`。
- 每一條規則都要過 mutation check：改掉那條規則，至少一個測試要變紅。實作完成時要逐條回報做過的 mutation check。
- 跑法比照既有測試，在 repo 根目錄執行：
  `node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test "tests/frontend/*.ts"`

**判斷花的模組（新增一個測試檔，放在 tests/frontend）**

- 四種勾選組合的真值表。
  - 用一組固定的混合資料，裡面有：普花、非普花、彩帶普花、彩帶非普花、普花花苞、蘑菇、煙霧。
  - 逐格驗證顯示結果，蘑菇和煙霧在每一格都顯示。
- 普花只認四個 key：
  - `f:White:Geranium`、`f:White:Cherryblossom`、`f:Purple:Common` 都不是普花。
  - 如果有人把規則改成「品種是 Common」，`f:Purple:Common` 那個測試要變紅。
- 花苞（合成資料：state 用 Leaf、Bud、Pre-Flower、pre_flower 等不同寫法，而且帶著落在彩帶期內的盛開時間）：
  - 永遠不會被判成彩帶花。
  - 勾只顯示彩帶時被藏掉。
  - 普花的花苞在取消顯示普花時被藏掉。這條依 key 判斷，用真實的花苞資料即可。
- 彩帶期邊界：
  - 剛好在 `bloomedMs` 那一刻是彩帶花。
  - 盛開後 59 分 59 秒是；剛好滿 60 分鐘不是。
  - 還沒到 `bloomedMs` 不是。
  - `bloomedMs` 或 `wiltingMs` 是 0 不是。
  - `wiltingMs` 早於盛開後 60 分鐘時：
    - 彩帶期結束時間取 `wiltingMs`。
    - 時間剛好等於 `wiltingMs` 時已經不是彩帶花，即使離盛開還不到 60 分鐘。拿掉 `now < wiltingMs` 這個條件，這個測試要變紅。
  - 時間欄位是字串時不是彩帶花。
- 以上都是用傳入的伺服器時間判斷，不讀系統時鐘。

**初始值（擴充 tests/frontend/test_defaults.ts）**

- 沒存過時：只顯示彩帶是 false，顯示普花是 true。
- 存過的值原樣保留，包含四種組合。
- 缺少或不是布林值的欄位用初始值。
- 壞掉的 JSON，或不是物件的值（字串、數字、null、陣列），整份退回初始值。

## Out of Scope

- 原站的「花苞」篩選與「已收集花精」篩選。
- 每個花種單獨勾選。
- 原站「強制顯示彩帶花」的語意，也就是「其他花全部顯示、普花只留彩帶花」這種組合。四種勾法都組不出它，這是刻意的。
- 讓 prune 在彩帶期結束時就拿掉 marker。決定改成等圖層重建時才更新。
- popup 彩帶倒數每秒更新。原站會，這裡決定在打開當下產生一次。
- 照抄原站的彩帶圖樣。
- 後端或上游請求的任何改動，包括伺服器端篩選，以及救回原站已截斷的花。
- 蘑菇、煙霧的篩選行為。
