# 02 「瞬移+撈水果」按鈕只對彩帶花出現

Status: ready-for-agent
Blocked by: (none)
Type: feature
相關：`.scratch/pipi-flower-essence/spec.md`，2026-11-09 grilling 的 Q15

## 為什麼

2026-11-09 使用者說明了遊戲的機制，已經寫進 GLOSSARY 的**水果**：只有**彩帶花**在**彩帶期**內，有玩家在附近**種花**，才會結出水果。沒有彩帶的花，不管怎麼走都拿不到水果，只能**採精華**。

01 號票的 Q2 當時決定「在盛開期內的花」都出現這顆按鈕，那時還不知道水果只有彩帶期才會結。結果是對沒有彩帶的花按「瞬移+撈水果」，等於白走一趟。

Q15 決定把這件事另開成這張票，不併進拿過精華的功能，以免兩件事混在同一個 commit 裡。

## 做什麼

只有在打開 popup 的當下是彩帶花的花，才出現「瞬移+撈水果」按鈕。

- 盛開超過 60 分鐘、已經沒有彩帶的花不出現。
- 花苞、蘑菇、煙霧照舊不出現。

撈水果本身的流程都不變：起點正東 35 m、直線走、瞬移失敗就中止、群組模式、最近地點。

## 驗收條件

- [ ] 撈水果按鈕的判斷改成彩帶花的規則：用打開 popup 當下的伺服器時間，跟 popup 的彩帶倒數行用同一個判斷，邊界也一樣。
- [ ] popup 打開之後才剛好結束彩帶期的花，按鈕還是在，按下照樣執行。這跟其他「打開 popup 時判斷」的項目一致，不另外處理。
- [ ] 測試，擴充既有的花的規則測試：
  - 彩帶花有按鈕；盛開後剛好滿 60 分鐘就沒有。
  - 剛好在盛開那一刻有；還沒到盛開時間沒有。
  - `wiltingMs` 早於盛開後 60 分鐘時，到了 `wiltingMs` 就沒有。
  - 沒有枯萎時間的花：照彩帶花的規則判斷，沒有按鈕。這是跟舊條件的差別，要寫明。
  - 三種寫法的花苞、蘑菇、煙霧都沒有。
  - mutation check：把條件換回舊的「盛開期內」，至少一個測試要變紅。
- [ ] GLOSSARY 的**撈水果**補上「對彩帶花」。例如：「先瞬移到彩帶花附近、再走到花上，讓遊戲沿路種花，藉此拿到那朵花的水果的動作。」
- [ ] 文件：
  - 蘑菇地圖設計文件撈水果一節的「When it shows」，改成彩帶花，並寫明原因。
  - 01 號票保留當時的決定，不改內容，只在它的 Comments 加一行，指向這張票。
- [ ] 人工驗證，逐項回報：
  - 彩帶花的 popup 有撈水果按鈕，沒有彩帶的盛開花沒有。
  - 打開 popup 時看到的彩帶倒數行，跟有沒有按鈕一致。
- [ ] 回歸：`tests/frontend/*.ts`、`tests/pipi/` 全部照跑，`npm run build` 要通過。有任何 skipped 都要說明。
